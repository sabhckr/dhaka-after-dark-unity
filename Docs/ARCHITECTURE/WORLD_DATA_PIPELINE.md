# World data pipeline

> **Superseded on 2026-11-06.** The city is now generated by `Tools/worldgen/build.sh [seed]` (seed 1971) from the owner's layout and imported models, not exported from OpenStreetMap; see [CITY_REBUILD.md](../PRODUCTION/CITY_REBUILD.md). `Tools/sync-world-data.sh` and the `Tools/layout` planner were moved to the Trash with the old map. The rest of this page is kept as the record of the old pipeline; the DADC format and its reader below are still the ones in use.

The geography is never edited in Unity. It comes from OpenStreetMap through the dhaka-after-dark repository, and Unity reads a generated, verified copy.

```
OSM bangladesh.osm.pbf (Geofabrik, ODbL)
  → scripts/geo/generate.ts            dhaka-after-dark: public/world, schema v2, 1,303 chunks of 500 m
  → scripts/unity/export-chunks.ts     DADC binary chunks, places, landmarks, world.json   (dev/architecture, 7b4ea2c + 2ebf234)
  → scripts/unity/verify-chunks.ts     exact round trip, hashes, positions
  → Tools/sync-world-data.sh           into Assets/StreamingAssets/World, writes WorldData.lock
  → Unity: Dad.World DADC reader (C#, verified on Unity's Mono) → chunk builders → streaming   (builders: Phase C)
```

Engine-independent canonical data (`scripts/canonical/*`, WGS84 GeoJSON with provenance) exists for the Farmgate / Kawran Bazar box, and it matches v2 to within 7 mm. When the canonical store covers the city and reads multipolygon relations, the generator will read from it. The DADC step will not change.

## Frame

| | three.js / v2 | Unity / DADC |
|---|---|---|
| Axes | x east, y up, z **south** (right-handed) | x east, y up, z **north** (left-handed) |
| Conversion | | `unity.x = x`, `unity.z = -z` |
| Origin | UTM 46N E 230000, N 2615000 (EPSG:32646) | same |
| Units | metres, quantised to 1 cm | integer centimetres in files, metres in the engine |
| Chunk `c_ix_iy` | covers x ∈ [500·ix, 500·ix+500], z ∈ [500·iy, 500·iy+500] | south-west corner at (500·ix, −500·(iy+1)); `world.json` lists it as `cell` |

A mirror flips polygon winding. Readers must not assume a winding. Compute it from the signed area, and triangulate either way.

## DADC format, version 1

The full specification is the field table in `scripts/unity/dadc.ts`. Summary:
- **Header:** `"DADC"`, format byte, source schema byte, `ix`, `iy`.
- **String table:** shared by all records, in first-use order.
- **Layers:** 16 in fixed order: roads, buildings, water, canals, parks, rails, plazas, bridges, trees, landmarks, graph nodes, graph edges, points, landuse, barriers, power.
- **Records:** required fields, then a presence mask, then the optional fields that are present.
- **Integers:** zigzag LEB128 varints. OSM ids exceed 2³², so C# reads them as `long`.
- **Positions:** centimetres from the chunk's south-west corner. Point lists are delta-encoded.
- **Derived ids:** graph node ids (`n<x cm>_<z cm>`) and edge ids (`w<way>:<seq>`) are rebuilt by the reader. The encoder refuses to export ids that do not follow the pattern.
- **Strictness:** the encoder refuses unknown keys and any value that is not an exact multiple of its unit. So a successful export is lossless by construction, and the verifier proves it per chunk.

## Reproduce

```bash
Tools/sync-world-data.sh ~/Documents/dhaka-after-dark-arch
```

It exports, verifies, and writes `WorldData.lock`. The lock records the source commit, whether the source tree had local changes, and the `world.json` hash. The data folder is gitignored, because it is ODbL data that can be regenerated byte for byte.

## Not covered yet

- **Elevation:** v2 is flat (y = 0). No DEM has been chosen; any download needs owner approval.
- **Multipolygon buildings** are missing from v2: 9 in the Farmgate test box.
- **Signs and assets** in `public/world/signs` and `assets/` are not part of this pipeline; their licences are tracked in the web repository.
